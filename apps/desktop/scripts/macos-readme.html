First launch on macOS

⚡ Quick fix (recommended)

Downloaded helper scripts can be quarantined too, so this ZIP does not rely on double-clicking a .command file. Use Terminal instead — commands you paste are not blocked the same way.

1. Open Terminal (Spotlight → type Terminal).
2. Paste one of the commands below and press Return.

Option A — one command (finds the app)

Works if the app is in /Applications, your current folder, ~/Downloads, or ~/Desktop: 

curl -fsSL https://github.com/midrissi/4d-dataexplorer/releases/latest/download/fix-macos-quarantine.sh | bash
👁 View script on GitHub 📄 View raw ⬇️ Download .sh 📚 Docs page

Option B — app still in the unzipped folder

In Terminal type cd then a space, drag the unzipped folder into the Terminal window, press Return, then paste: 

xattr -cr "Data Explorer.app" && open "Data Explorer.app"

Option C — direct one-liner (app in Applications)

xattr -cr "/Applications/Data Explorer.app" && open "/Applications/Data Explorer.app"
Inspect before running: view on GitHub · download .sh · docs guide. You can also pass a path: bash fix-macos-quarantine.sh "/path/to/Data Explorer.app".

macOS may block this build because it is ad-hoc signed but not Apple-notarized. That often looks like “Data Explorer can’t be opened because Apple cannot check it for malicious software” or “is damaged and can’t be opened”. Clear the quarantine attribute with xattr -cr (or the curl script above), then open the app.

🧭 Step-by-step

  1. Unzip the download

    Double-click the .zip in Finder (or use Archive Utility). Prefer a local folder such as ~/Downloads — avoid network shares for the first launch. Optionally drag Data Explorer.app to /Applications.

  2. Open this README (optional)

    Double-click README.html anytime you need these instructions. It works offline; the curl command and website links need a network connection.

  3. Clear quarantine in Terminal

    Use Option A, B, or C in the Quick fix section above. That runs xattr -cr on the app (and Option A / B / C can also open it).

  4. Launch the app

    If it did not open automatically, double-click Data Explorer.app. After a new download, run the fix again on the new copy.

🖱️ Alternative: Right-click → Open

For a one-time Gatekeeper bypass without Terminal: right-click (or Control-click) Data Explorer.app → choose Open → confirm Open in the dialog. After that, normal double-clicks usually work for that copy of the app.

If macOS still says the app is damaged, use the Terminal / curl quick fix — the right-click path alone is often not enough for that message.

❓ Why does this happen?

Apple’s Gatekeeper expects apps distributed outside the Mac App Store to be Developer ID–signed and notarized. Data Explorer’s CI builds are ad-hoc signed (enough for a valid code signature locally) but not notarized, so downloaded copies get a quarantine extended attribute (com.apple.quarantine).

Clearing that attribute with xattr -cr tells macOS you trust this local copy. It does not disable Gatekeeper system-wide. We do not ship a double-click .command fixer because that file would be quarantined too.

Notarization requires an Apple Developer Program membership and signing secrets in CI. Until those are configured, this README documents the Terminal / curl workaround.

🆘 Troubleshooting

curl: command not found / network error

Use Option B or C instead (plain xattr — no download). Or fetch the script when online: 

curl -fsSL https://github.com/midrissi/4d-dataexplorer/releases/latest/download/fix-macos-quarantine.sh | bash
Script says it can’t find Data Explorer.app

cd into the folder that contains the app, move it to /Applications, or pass the path: 

curl -fsSL https://github.com/midrissi/4d-dataexplorer/releases/latest/download/fix-macos-quarantine.sh | bash -s -- "/path/to/Data Explorer.app"
Still blocked after xattr

Try:

xattr -l "/path/to/Data Explorer.app"
xattr -cr "/path/to/Data Explorer.app"
codesign --verify --deep --strict --verbose=2 "/path/to/Data Explorer.app"

Re-download from the latest GitHub release if the archive was truncated. Prefer the architecture-matched ZIP (aarch64 for Apple Silicon, x86_64 for Intel).

Wrong CPU architecture

Apple Silicon Macs need the aarch64 build; Intel Macs need x86_64. Check Apple menu → About This Mac, then download the matching asset from Releases.

Updates and auto-updater

Once running, the desktop app can check GitHub Releases for newer signed builds. See the docs site and repository updater notes. Fresh browser downloads may need the quarantine fix again; in-app updates follow the signed updater path.

# then run the container and open http://localhost:8080/dataexplorer/

Or download DataExplorer.zip and extract it into your 4D server’s Resources/WEBJS/ folder. Full steps: Getting started.
