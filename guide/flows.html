Flows ​

Flows is a visual canvas for building and running data and request pipelines against the connected 4D REST server. Wire blocks together, debug with breakpoints, and optionally let Flows AI edit the graph with tools. See named parts.

Open from:

  • Status bar Flows control
  • Command palette (Flows)
  • Welcome screen Operators tour (loads a starter template)
  • Assistant navigation tools

Flows are saved per database (BASEID) on this device. File-backed flows (desktop / mobile) keep only a path reference in that store; edits auto-save to the JSON file in a trusted folder.

Workspace ​

The editor has four areas:

AreaPurpose
LibrarySaved flows for this database — search, duplicate, delete, clear all; import / export / copy JSON. On desktop and mobile, Open from trusted folder and Save to trusted folder use a file picker (folders + explorer, no preview pane) with a type filter (JSON or All files). File-backed flows keep only a path reference in the store; edits auto-save to the JSON file.
CanvasStart and End anchors plus connected blocks; drag from the palette, drop on an edge to insert
Outline / NodesSearch and multi-select blocks; add from the palette
DockInspector, run log, and Flows AI — collapse or expand from the toolbar

Double-click a block name (or use the pencil) to rename. Select a block or edge, then Delete / Backspace to remove it. Auto-organize lays the graph out.

File-backed flows show a drive icon. Open it for the path, Open in Files, and Reload. Removing a file-backed flow asks whether to unlink it from the library or also delete the JSON file. Clear all unlinks file-backed flows without deleting files.

Disable a block to skip it at run time (not available on Note blocks). Open Method and HTTP nodes in the Method Executor or HTTP Client when you want the full request UI.

Operator tooltips (palette and canvas) include a RxJS documentation link for named operators; on desktop that opens in the system browser.

Blocks ​

Palette categories:

CategoryBlocks
InputsInject (payload, including $faker numbers), Interval ({ counter, timestamp }), Timestamp
DataList (one or more dataclasses), Create, Generate, Update, Purge (query / entity set / full dataclass), CSV import
NetworkHTTP, Method (catalog / singleton / dataclass / entity)
CodeSet variables, Evaluate (sandboxed TypeScript main()), AI prompt
LogicIf, For, Repeat each, Delay
OperatorsRxJS-style Map, Filter, Take, Merge, ForkJoin, Buffer, Debounce, and related operators
FilesFile ({{$files.alias}} on desktop / mobile)
MiscStart, End, Log, Timing timeline, Note (Markdown — skipped at run; cannot be disabled or take a breakpoint)

Start and End are always present and cannot be removed. Inputs blocks are sources: they have no inbound port and fire when you run the flow (Interval keeps emitting until its count is reached or you stop).

Templated fields resolve environment variables at run time ({{vars…}}, {{nodes.id.stdout}}, $faker, $this, …). CSV imports support dataInit-style $rel_* relation columns, dependency-ordered waves, and optional skip-when-not-empty.

Generate (bulk create) ​

Generate inserts many entities with the same field templates. $faker and $pick stay unresolved until each row is created, so names, addresses, and pictures differ across the batch (REST createMany, chunks of 100).

Use Create for a single row (or an explicit entities array). Prefer Generate when count is greater than 1.

Zip foreign keys ​

On a Generate block, Zip from parent lists copies a sequential value onto each new row:

Inspector fieldMeaning
Field (FK)Attribute on the new entity (for example address or comp_id)
From pathBinding to a previous result, usually nodes.addr_hq.stdout.entities
Parent attrAttribute to copy (default ID, with __KEY fallback)

When zip is set, count follows that list length. Two zip columns must be the same length (for example staff addresses and repeated companies).

Wire one inbound edge into a Generate in port. Extra edges from an earlier parent (for example companies → staff addresses and Repeat each → staff addresses) overwrite the input: the last edge in the graph can run Generate before Repeat each finishes, so zip lists mismatch (often length 1 vs N).

Use zip when each parent must get a deterministic number of children. Use {{$pick|from:ds.Parent.ID}} only when a random FK from the pool is enough (counts per parent will be uneven).

Repeat each ​

Repeat each (Logic palette) is CPU-only: it takes the inbound entity list (including a generate result’s entities) and emits a flattened list — each parent repeated N times. N can be a number or a template resolved per parent, for example {{$faker.number.int | between:10,50}}.

Typical seed:

  1. Purge dependents first (one block, several dataclasses)
  2. Generate parent rows (for example 100 addresses, then 100 companies zipped to those IDs)
  3. Repeat each on the companies
  4. Generate child addresses with count {{nodes.staff_slots.stdout.length}}
  5. Generate children zipped to those addresses and the repeated company list

Do not put Create/Generate on for.item for bulk inserts — that is one REST round trip per row.

Images in generate ​

{{$faker.company.logo}} and {{$faker.image.personPortrait}} resolve to compact SVG data URIs (optional | female / | male on portraits). They do not download from a CDN before $upload, so large employee batches stay fast.

Run and debug ​

The run toolbar:

  • Run / Pause / Resume / Stop
  • Step over
  • Dry run and optional Verbose
  • Per-block breakpoints, with a global enable/disable (step over still pauses). Notes cannot take a breakpoint
  • Follow current step pans the canvas to the running block
  • Status bar Flows control expands with progress while a run is active

The Log dock shows run output. Settings → Flow logs limit keeps the last N lines across runs (0 = unlimited; you can still clear the log). Verbose logs each block as pending then done (or error), with duration next to the line, copy beside the text, and expandable Inputs / Outputs (same object tree as the Console). A dry-run Summary row is collapsible and lists record counts grouped by action (create, update, delete, CSV import) then dataclass, plus CSV files, methods, and HTTP calls. Collapse all (next to Clear, or from the log context menu) folds expanded rows without clearing the log. At a breakpoint, add watches and evaluate expressions (inputs.in, vars, nodes…) in the run console.

REST traffic from HTTP / Method / data blocks appears in Console → Network.

Run on server ​

When the base exposes FlowRunner and the flow has no client-only nodes (CSV and File need the desktop or mobile app), Run on server executes on 4D instead of in the browser.

Flows AI ​

The AI dock tab builds optimized flows from a prompt and refactors the current graph with tools (instead of dumping JSON). It prefers batched generate (and zip / repeatEach for parent–child data) over per-row for + create. Configure an LLM in Settings — the same providers as the AI assistant.

Starter prompts include adding a timing block, CSV + photos from trusted folders, optimize for speed, and simplifying a complicated graph.
